## 🧠 3. High-Yield Interview Technical Q&A

### Q1: Why did you choose FAISS Inner-Product (`IndexFlatIP`) instead of L2 Euclidean Distance?
**Answer:**
> *"When working with text and multimodal embeddings generated by models like Sentence Transformers, directional similarity (the angle between vectors) is more semantically meaningful than raw Euclidean magnitude. By L2-normalizing all embedding vectors prior to insertion, the Inner Product mathematically equals Cosine Similarity ($\mathbf{u} \cdot \mathbf{v} = \cos(\theta)$), which allows FAISS to execute ultra-fast dot-product matrix multiplications with sub-5ms latency."*

### Q2: How did you design the Temporal Video RAG pipeline to prevent LLM hallucinations?
**Answer:**
> *"Video data is high-volume and unstructured. Instead of dumping raw frames directly into an LLM context window (which is cost-prohibitive and slow), I implemented a two-stage retrieval pipeline:*
> 1. *Stage 1 (Vision & Extraction)*: YOLO and OpenCV extract structured bounding boxes, confidence scores, spatial velocity, and dwell times per frame.
> 2. *Stage 2 (Vector Indexing)*: These structured telemetry logs are vectorized with Sentence Transformers into FAISS.
> 3. *Stage 3 (Grounded Prompt Injection)*: When an incident report is requested, the system retrieves only the top-k relevant timestamped evidence blocks and injects them into the Groq LLaMA-3.3 prompt with explicit instructions to cite camera IDs and exact timestamps, ensuring 100% factual grounding."*

### Q3: How does the FastAPI backend maintain high throughput without blocking?
**Answer:**
> *"FastAPI is built on Starlette and `asyncio`. I separated the synchronous CPU-intensive inference tasks from the asynchronous API handlers. Long-running stream telemetry is served through async generators, while SQLite/PostgreSQL queries use non-blocking connection pools, enabling the platform to handle multiple concurrent operators and telemetry streams without latency spikes."*

### Q4: How is authentication handled between JWT and Firebase?
**Answer:**
> *"The backend supports a dual-layer auth mechanism: standard HS256-signed JWT access tokens for stateless session management with configurable expiration, alongside a Firebase Auth token verifier that decodes Google Firebase ID tokens to extract role-based access control (RBAC) claims like Operator vs Super Admin."*
